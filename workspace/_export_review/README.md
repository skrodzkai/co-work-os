# _export_review — the only door out

Nothing leaves this workspace — to a wider audience, a lower tier, an email, a deck for
another team — except through this folder, after a **human** review. Anyone (including
Claude, when asked) may stage a candidate file here; only a human reviewer moves it onward.

**The export checklist** (the reviewer confirms every line):

- [ ] Identifiers stripped — no names, employee IDs, or values traceable to one person
- [ ] Every reported group has **n≥5** people
- [ ] The next-smallest group is suppressed too, so no cell can be reverse-derived by
      subtraction from a total
- [ ] No quasi-identifier combinations — level × location × tenure can be a name
- [ ] The receiving audience is appropriate for this content
- [ ] The file name itself is clean (dates and topics, nothing sensitive)

The n≥5 and next-smallest-suppression rules are the floor, not a guarantee. When a pack has
several tables that share a population, a cell suppressed in one can be re-derived from
another, and totals can leak a suppressed cell by subtraction across tables. For anything
with multiple cross-tabs, small populations, or protected-class cuts, don't rely on this
checklist alone — route it to your privacy/legal reviewer.

**Why a folder and not just a rule:** the realistic leak isn't the AI — it's a person
dragging a file from a confidential tree into a shared one. One named door makes the
crossing a deliberate act, visible in the tree, instead of a drag-and-drop accident.

After review, the reviewer (not Claude) moves the file to its destination and deletes the
copy here.
